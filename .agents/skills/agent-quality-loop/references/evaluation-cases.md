# AQL Core Evaluation Cases

After a material workflow, contract, or boundary change, run the bundled structural validator, then forward-test these cases using only the single AQL Skill and the raw request. Structural checks establish mechanics; they do not prove user benefit.

## 1. Narrow Local Fix

Align an observable goal, inspect before editing, make the smallest authorized change, run focused verification, and stop at `BUILT`. Do not deploy or invent independent acceptance.

## 2. Formal Acceptance

A fresh acceptor reads contract, artifact/diff, and raw evidence before the implementer narrative. It grants `ACCEPTED` only when every required dimension has concrete PASS evidence. Same-context self-review remains `BUILT`/`PENDING`.

## 3. Release Boundary

Acceptance does not authorize release. A release preflight is separate; publish/deploy requires a current-turn, target-specific authorization.

## 4. Semantic Ambiguity

Distinguish display, data, and capability changes. If repository evidence cannot resolve an outcome-changing ambiguity, remain read-only and ask one grounded question.

## 5. Code Execution

The built-in code adapter consumes the aligned/evidenced contract, re-reads targets, plans the smallest root-cause repair, protects semantic must-holds, self-checks, and returns one receipt capped at `BUILT`.

## 6. Acceptance Findings

A demonstrated required-dimension defect is `FAIL`; unavailable evidence or independence is `BLOCKED`/`PENDING`; advisory taste feedback cannot defeat otherwise evidenced required dimensions.

## 7. No Profile

An absent, unreadable, disabled, paused, or inaccessible `$AQL_HOME/profile.json` leaves the Core workflow fully functional. Only an explicit profile-management request receives an access error.

## 8. Explicit Memory

“From now on, answer concise Chinese conclusions” may create a low-risk entry and reports saved value, scope, and revocation. A semantic alias, working identity, or decision-changing preference is restated and requires confirmation.

## 9. No Inferred Memory

Repeated choices, corrections, silence, output acceptance, and inferred traits create no candidate, counter, cross-task prompt, activation, or write. An unconfirmed same-task correction is discarded at task end.

## 10. Projection

Only complete active, relevant entries enter Guided, at most two. Current-turn instructions win. Unknown applicability, review-due entries, incomplete entries, and same-key conflicts are suppressed. A profile never changes authority, evidence, acceptance, release, or project rules.

## 11. Fresh Mode

Skip stored preferences only. Preserve current instructions, project facts/rules, lessons, authority, evidence, acceptance, and release boundaries. Do not write profile data.

## 12. Privacy

Ordinary results do not reveal profile contents, projection machinery, or capability receipts. A profile-management result states saved/changed scope and revocation.

## 13. Project Scope

`.aql/project.json` is absent unless the user confirms a project-scoped preference save. When created it carries only schema and opaque project identity.

## 14. Portability

Agents sharing an accessible same-machine `$AQL_HOME` read the same JSON. Remote, container, cloud, and other-device access is unsupported unless a controlled mount exists; other-device transfer is explicit export/import, with no default upload.

## 15. Capability Receipt

Every capability state has installer, host fact, configuration, local-probe, or actual-call evidence. Model self-report is rejected; unknown/unrun is `NOT_RUN`. A receipt is temporary and cannot become profile, lifecycle, authority, or Task Contract state.

## 16. Result Attention

Routine success leads with conclusion and decisive evidence in 1–3 lines. Internal profile/receipt details appear only on request, formal audit, handoff, or a material blocker.

## 17. Validated Profile Mutation

An explicit profile change uses the packaged CLI/runtime with schema validation, expected-revision CAS, locking, atomic replacement, and managed cleanup. The agent never free-form edits `profile.json` or `.aql/project.json`; when the control plane is unavailable, only the requested management operation fails and Core work continues without profile application.

An applied 2.8 migration captures source bytes once, derives both entries and backup from them, merges with an existing Profile, and rejects id collision or an impossible CAS before any mutation. Output failure after a successful commit must not roll back a project identity that committed Profile entries now reference.

Scoped `forget` removes every matching owned record that can contain the entry body; `forget --all` selects all entries inside the locked mutation and removes all records owned by that Profile. Commit failure leaves cleanup targets intact; cleanup failure restores the prior Profile. A missing/wrong marker, closed-metadata or inventory/type/hash drift, path exchange, or link escape fails without deleting external content. Automatic-backup and receipt cleanup preserves unowned filename/string-match lookalikes and handles Windows path casing by filesystem identity.

## 18. Negative Trigger

One-line factual answers, translation, and casual brainstorming do not require reading this skill. Near-neighbor mentions of acceptance/release/contract stay dictionary or chat work.

## 19. Standard Acceptance

A bare「验收」request is result-anchored free review: after-state, hard boundaries, and claim limits, in plain prose. No dimension table, no `not_applicable` ceremony, no release language.

## 20. Formal Conjunction

`assurance: formal` or release-bound accept keeps the four always-required dimensions conjunctive. Envelope validators are not relaxed.

## 21. Observer Cap

`agent_review` cannot produce `user_observable_result: PASS`. That PASS needs native-medium / runtime evidence plus `mechanical_runtime` or `human` with a role.

The package is behaviorally ready for a claimed host only when these cases pass on the exact package bytes. Product benefit requires a separately preregistered comparison; no structural or fixture result proves long-term user value.
