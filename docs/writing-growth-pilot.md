# Writing Collaboration and Growth Pilot

Status: `NOT_RUN`.

This protocol tests two separate questions and never collapses them into one score:

1. Does the writing adapter improve or preserve the current artifact and collaboration cost?
2. Across repeated tasks, is there evidence that the user needs less scaffolding while retaining transferable judgment?

Static cases and validators can accept the mechanism. They cannot change this longitudinal status.

## Six-task minimum

Use six real, consecutive writing tasks with comparable difficulty coverage: factual/explanatory, persuasive/strategic, teaching, creative/narrative, revision/editorial, and author-tool outline. Do not manufacture tasks merely to fill rows.

For each task, derive observations from the existing canonical contract/envelope history, implementation receipt, acceptance evidence, and explicit user corrections. Do not create a second exposure/event database and do not retain full raw prompts by default.

| Surface | Per-task observation |
|---|---|
| Contract compile | expected terminal; compiled outcome; consumer/medium; truth mode; fixed constraint retention; silent added constraints; material questions; user corrections/restarts |
| Artifact quality | cold-reader result if run; claim/source defects; structural breaks; material omissions; counterexample result; reopen/rework |
| Collaboration cost | question count; unnecessary confirmations; visible ceremony; time-to-BUILT; time-to-ACCEPTED when requested |
| Profile safety | matched active ref; candidate vs active; current-turn override; stale/mismatched fire; authority-shaped refusal; inspect/edit/delete outcome |
| Growth | user can explain consumer/goal and one key trade-off; scaffolding level; quality after a deliberate scaffold reduction; transfer outside a fixed template |
| Diversity | repeated structures/voice without a task reason; alternative strategy remained available |

## Outcome rules

- Current artifact: use the existing domain/self-QA/acceptance evidence. Do not infer user growth from it.
- Collaboration/profile association: descriptive only. `injected_refs` absence is measurement unknown, not evidence of no influence.
- Growth Focus: include only an explicitly confirmed active focus; a candidate never counts as applied.
- `PASS`: only after the six-task set supplies readable repeated-task evidence for the stated growth observable without unacceptable artifact-quality or personalization-safety regression.
- `FAIL`: a stated longitudinal observable is contradicted, or profile/scaffold behavior creates a repeated quality/safety regression.
- `PILOT`: tasks exist but the sample or comparability is not yet sufficient for a longitudinal conclusion.
- `NOT_RUN`: fewer than six real consecutive tasks or no readable evidence set. This is the current state.

No result authorizes causal marketing without a suitable comparison design. Never optimize engagement, time-on-task, user dependence, or similarity to past prose as the primary reward.
